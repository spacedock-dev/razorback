### B. Verifier expectations

`harbor/verifier/verifier.py:200-210` (harbor 0.6.6) checks **on the host filesystem** for `trial_paths.reward_text_path` then `trial_paths.reward_json_path`, both resolving via `harbor/models/trial/paths.py:199-211` to `trial_dir/verifier/reward.{txt,json}` — the **trial-root** `verifier/` mount target (NOT `steps/main/verifier/`). The dual-path multi-step relocation contract is documented at `harbor/models/trial/paths.py:100-106`: "agent/, verifier/, and artifacts/ exist at the trial root only transiently as mount targets for the environment; their contents are relocated into steps/{step_name}/ after each step".

Who is supposed to write the reward file: the **verifier test script** (`tests/test.sh`), which `harbor/verifier/verifier.py:185` runs inside the container via `environment.exec(command)`. For DAB bookreview, that script is generated by `src/razorback/benchmarks/dab/prepare.py:228-237` `_test_sh` and writes to `/logs/verifier/reward.json` via `python /tests/verify.py ... --reward-out /logs/verifier/reward.json`.

The contract: the container's `/logs/verifier/` is **bind-mounted** from the host's `trial_paths.verifier_dir.resolve().absolute()` per `harbor/environments/docker/docker.py:193-200` (`HOST_VERIFIER_LOGS_PATH` env var) and `harbor/environments/docker/docker-compose-base.yaml:3-9` (`type: bind`, `source: ${HOST_VERIFIER_LOGS_PATH}`, `target: ${ENV_VERIFIER_LOGS_PATH}`). When the container writes `/logs/verifier/reward.json`, the bind mount should surface it at the host path harbor checks. The container reports `EnvironmentCapabilities(mounted=True)` (`harbor/environments/docker/docker.py:238-243`), so harbor's verifier code path **skips** the download step (`harbor/verifier/verifier.py:190-199`, guarded by `if not self._environment.capabilities.mounted`) — it trusts the mount surfaces the file directly.

## Root cause

The v1 bookreview "regression" is **not a regression in razorback or harbor code**. It is a **run-invocation defect**: the baseline at HEAD `2a2be8c` was executed with `--runs-dir /tmp/razorback-baseline-20260520`, which on macOS resolves to `/private/tmp/...`. Colima's VM bind-mounts ONLY `/Users/clkao` (confirmed by `colima ssh -- mount`: `mount0 on /Users/clkao type virtiofs`). Host paths under `/private/tmp/` are invisible inside the Colima VM, so docker-compose's bind mounts at `harbor/environments/docker/docker-compose-base.yaml:3-9` (`source: ${HOST_VERIFIER_LOGS_PATH}` ← `trial_paths.verifier_dir.resolve().absolute()` from `harbor/environments/docker/docker.py:193-195`) resolve to a non-existent VM-side path. The container's `/logs/verifier/` is therefore backed by VM-local tmpfs, not the host. When `test.sh` writes `/logs/verifier/reward.json`, the write succeeds inside the container but never reaches the host. Harbor's verifier then checks the host path at `harbor/verifier/verifier.py:201-210` (skipping the download fallback at lines 190-199 because `capabilities.mounted=True` per `harbor/environments/docker/docker.py:238-243`) and raises `RewardFileNotFoundError`. M5 succeeded on the same image/code because its driver — `tests/integration/test_rk_run_bookreview_claude.py:46` — routes `--runs-dir` through the `colima_safe_tmp_path` fixture (`tests/conftest.py:12-23`), whose docstring at `tests/conftest.py:14` explicitly states the constraint: "A tmp dir under /Users/... that Colima mounts into the docker VM." The constraint exists in the codebase but is enforced ONLY via the test fixture; the CLI `rk run --runs-dir <path>` accepts any path and silently produces 100% failures when the path is outside Colima's mount scope.

Contributing factors (each is a real defect on its own, but none is the primary cause):

1. `src/razorback/agents/claude_cli.py:118` calls `environment.exec(cmd, env=self._exec_env, timeout_sec=600)` and **ignores the return code and stderr**. If claude exits non-zero or produces no output, the trial proceeds to verification with no signal that the agent failed. This is independent of the mount issue, but it masks failure modes and would have made this same regression harder to diagnose if it had a different proximate cause.
2. Harbor 0.6.6's docker environment does not validate that bind-mount source paths are visible to the VM. The mount succeeds at compose-up time even when virtiofs cannot resolve the source; this is a Docker-on-macOS-with-Colima class hazard, not a harbor bug per se, but a `mkdir`-then-stat probe at start-of-trial would catch it.
3. The razorback CLI has no `--runs-dir` validation against `colima_safe_tmp_path`'s constraint; the constraint is encoded in a pytest fixture's docstring but not in the runtime.

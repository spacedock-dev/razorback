  cleared with `captain-approved` rather than the usual
  `auto-approved per captain pre-auth`). Worth tightening the FO's
  dispatch-prompt generator to always read fresh from frontmatter
  rather than re-stating from session memory.

  through `validate → reroute → implementation → validate → reroute
  → implementation → validate → PASS`. Each cycle surfaced a new
  shape of data-isolation hole (cache isolation, db metadata,
  Airbnb preflight contract). The pattern was correct — captain's
  insistence on root-cause-fix-not-symptom-patch caught real
  regressions — but the cycle count suggests this entity could have
  benefited from a wider plan-stage probe (more sample task
  families upfront).

  uniformly honored across `BaseAgent` vs `BaseInstalledAgent`
  subclasses — the m2 entity is the followup to assess whether to
  surface this as a typed contract.

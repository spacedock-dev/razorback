## Issues — Workflow

1. **Apples-to-oranges headline metric.** Razorback's `rk score` binarizes pass@1 to per-trial all-or-nothing (1.0 only if ALL queries pass that attempt). Paper's `per_query_pass_at_1` in `~/git/dataagentbench/benchmark/lib/analysis.py:870` is continuous (per-query passes / trials, then averaged across queries within dataset, then averaged across datasets). Our 0.500 inside [0.254, 0.746] vs paper's 0.577 framing compared two different metrics. A real reproduction requires computing our pass@1 the paper's way using `validation.json` per-query data.

2. **Worktree teardown destroyed `runs/` artifacts.** FO ran `git worktree remove --force` after goal1-resume merge. The gitignored `runs/goal1-resume/` (per-cell `validation.json`, `reward_per_query.json`, session jsonl traces, `audit-aggregate.json`, freeze trees) went with it. Per-query rescore against paper's metric is now impossible without re-running. Cost reconstruction unverifiable from local state. Four follow-up entities filed (`x9`, `jp`, `f1`, `z5`) to close this structurally.

3. **Freeze trees lived under the destroyed worktree.** spacedock_solver_v2's halt/resume design materializes sealed_hash-keyed freeze trees that COULD have enabled re-score-without-re-run. They were at `<run-dir>/_razorback/freeze/...` which == worktree-relative gitignored path. Same teardown destroyed them. `f1 freeze-tree-content-addressable-store` is the structural fix.

4. **PKG-15 mongo healthcheck unit test was insufficient.** Validated the `retries=60` field in task.toml but did NOT validate the probe command was executable inside the agent container. `mongosh` binary not in `dab-agent:latest`; probe ran rc=1 every retry until timeout. Real fix required `pymongo` rewrite during goal1-resume implementation (commit `faefc77`). Worth a follow-up: all healthcheck/probe unit tests should assert the probe binary's presence in the target container, not just the YAML emission.

5. **Three follow-up bugs landed inside goal1-resume's worktree** (not their own entities): (a) mongo probe binary fix (`faefc77`); (b) `ClaudeCliAgent` inner via `_runtime/claude.py` was building harbor's `ClaudeCode` directly, bypassing PKG-26's subclass (`e3d3f1c`); (c) `SpacedockSolverAgent.populate_context_post_run` did not delegate to inner agent (`e8cec00`); (d) the inner's `claude-code.txt` path mismatch (`<trial>/agent/claude-code.txt` vs the expected `<trial>/claude-code.txt`) left cost_usd null on disk and `claude-output.jsonl` symlink missing despite the subclass — NOT fixed this session; remains the cost-on-disk + audit-coverage gap reported in goal1-resume's stage report. Worth filing as a separate entity for next session.

## Issues — Spacedock

1. **First-officer contract treats `git worktree remove --force` as benign cleanup.** No safeguard against destroying experiment artifacts. The `--force` flag is the warning signal (untracked files exist) but the contract doesn't require auditing them before destruction. `z5 fo-no-force-worktree-remove` is the local fix; worth a parallel spacedock GitHub issue + a shared-core update.

2. **FO mis-prefixed entity slugs as `pkg22..pkg27`.** sd-b32 IDs are the unique reference; sequential PKG-N prefixes collide with parallel codex-side agents. Captain caught it mid-session; later entities (harbor-dab-batch-query-mode, spacedock-solver-v2-freeze-dir-mount, and the 4 ergonomics filed today) used descriptive slugs. Worth a shared-core addition: "Entity slugs SHOULD be descriptive; never use sequential prefixes since sd-b32 ID is the unique ref."

3. **`claude-team build` helper consumed enormous prompt content** by inlining the full impl stage report + plan + entity body in every dispatch. Resulted in FO context-pressure on the long session. Worth either truncating prior stage reports in dispatch prompts or making the inline opt-in.

4. **`status --next-id` rejected a stray non-entity .md file** at workflow root (`pkg26-validation.md` was a worker's evidence doc, not an entity). The error was clear (`Error: invalid sd-b32 stored id`) but worth: (a) the directive that evidence docs belong under `_evidence/` should be in the workflow `README.md` template, (b) `status --validate` could surface stray files before they break `--next-id`.

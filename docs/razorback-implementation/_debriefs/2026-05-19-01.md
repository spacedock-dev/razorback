## Issues — Workflow

- **M3 OAuth token leaked plaintext to disk** — surfaced when the live
  ade-bench attempt printed CL's `~/.claude/benchmark-token` value in 4
  files of the run-dir (`lock.json`, `config.json` x2, `result.json`).
  Root cause: M3's `ClaudeCliAgent` forwarded auth via
  `AgentConfig.kwargs.resolved_auth_env`; harbor templatizes `env` but
  not `kwargs`. M3 validator did not grep the run-dir for the literal
  token. **Closed by FU-1.**
- **M7 ade-bench fixture image lacked `claude` on PATH** —
  `alpine:3.19 + apk add bash` only; `claude --version` exit 127 at
  agent setup. M7 validator approved without verifying claude reached
  `agent.run()`. **Closed by FU-2.**
- **DAB adapter served degraded-mode dump-file access** — single-service
  compose, agent gets `.sql` dumps and sqlite files; dataagentbench treats
  this as "postgres unreachable" fallback. M5's 0.6746 is not comparable
  to upstream DAB leaderboard. **Open as PKG-3, critical-path.**
- **Docker GC overreach** — FO ran `docker ps -q | xargs docker rm -f`
  after inspecting only the top 10 of 20 entries; killed CL's
  parallel-session containers (FU-1 implementor was on the same DAB
  stacks). Lesson learned, no code change; future GC must filter by
  name/age or inspect the full list first.
